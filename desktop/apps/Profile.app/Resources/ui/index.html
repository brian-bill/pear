The core OS

Vanilla is the layer below the desktop.

Vanilla provides everything under the interface: a kernel with a process model and Mach-inspired message passing, a Unix-style virtual file system persisted in the browser’s Origin Private File System, drivers that adapt browser APIs, system services and a POSIX-flavoured shell.

The file system engine is written in Rust and compiled to WebAssembly. Metadata lives in an index with a write-ahead journal, while file contents live in separate blobs. Mounting replays the journal, drops torn records and cleans up orphaned data — so a crash does not take the disk with it.

Processes are isolated by construction. Each one runs in a sandboxed iframe with an opaque origin, no storage, no network and no DOM; its only channel out is a MessagePort to the kernel. Apps are bundles with manifests, icons, permissions and launch services. The same rules apply to this Profile app as to anything else.

A real process model

spawn, signals, wait, pipes, PTYs and job control. Processes get a pid, a cwd, an environment and file descriptors.

Sandboxed by default

Opaque-origin iframes, a strict Content-Security-Policy and one narrow channel to the kernel. No ambient storage or network.

A Unix file system

files, directories, symlinks, extended attributes, trash, atomic writes and write-ahead crash recovery on OPFS.

Message-passing IPC

Mach-inspired ports with send rights, named services, requests, dead-name notifications and payload transfer.

A working userland

a shell with control flow, functions, here-documents and job control, plus 20 core programs in /bin.

Apps as bundles

install, update, verify and launch by file type or URL, with per-app permissions and single-instance behaviour.

Drivers as services

display, input, audio, clipboard and timers — browser capabilities behind the same IPC boundary as everything else.

Observability built in

a rotating system log, console bridge, crash reports, diagnostics and traces — the tools an OS needs to explain itself.

Design principles

Small. Fast. Isolated. Readable. Browser-native.

SmallFewer, well-defined primitives over feature breadth.
FastLazy-load everything non-essential; keep the boot path short.
IsolatedNo shared mutable state between processes.
ReadableA codebase that is a good place to learn how an OS works.
NativeUse the browser’s platform APIs directly. Avoid heavy frameworks.

The interface

The desktop is a client, not a privileged layer.

Every window, menu, dock icon and app talks to Vanilla through the same syscall interface. The window manager, launcher, Finder and this Profile app are all ordinary clients of the OS.
